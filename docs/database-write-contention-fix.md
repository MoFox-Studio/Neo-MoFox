# 媒体写竞争与消息 ID 作用域修复

## 日志与复现

2026-10-21 的日志包含三种数据库错误：

- 11:53:18：媒体 `UPDATE images` 等待写锁后报 `database is locked`。
- 11:58:55：两个任务同时查询到媒体不存在，随后重复插入，触发 `images.path` 唯一键冲突。
  日志中同一个媒体哈希的两条“创建新媒体记录”出现在同一秒。
- 02:22:01：`messages.message_id` 全局唯一键冲突。只读查询确认同一平台消息 ID
  已存在于另一个聊天流，而业务查询按聊天流查重，因此再次插入失败。

这些日志没有再次出现上次的 `Exception during reset` / `CancelledError`。
它们属于写入竞争与消息身份约束问题，取消清理保护仍然保留。

在临时文件 SQLite 中加载修复前的媒体写入代码，强制八个调用先完成查询再写入：
最终只有一条记录、计数为 1，另七次写入报错。新的并发回归使用独立池连接和多个
仓储实例，检查所有调用的计数、描述、识别状态及连接归还。

只读 `EXPLAIN QUERY PLAN` 还确认生产库媒体查询为 `SCAN images`：原先只有路径索引，
`hash OR path` 中的哈希字段没有索引，增加了查询及写锁持有时间。
日志不足以确定当时具体哪个连接持有写锁，不将其归因于某个插件。

## 实现

- 新增 `run_write_transaction`：同一 SQLite 引擎先在异步队列排队，等待期间不占连接；
  数据库事务在读取前执行 `BEGIN IMMEDIATE`，将查询后更新放在同一个短写事务中。
  只有原始 SQLite BUSY/LOCKED 错误会在完整回滚后使用新会话
  重试，最多三次，沿用配置的单次锁等待时间；其他异常与取消继续传播。
  回调只能使用提供的 Session 执行数据库操作，不能执行网络、文件等外部副作用。
  排队任务也会登记到引擎生命周期中，停机时与当前写入者一起取消、等待，防止释放连接池后补写。
- 图片、表情、语音、视频共用一个保存实现。目标路径命中优先，避免哈希和路径分别指向
  两条历史记录时修改路径撞唯一键；保留计数、已有描述和识别状态，不删除另一条记录。
  身份变更后刷新记录时间，使按哈希回查选中当前实际保存的路径。
- 首次插入使用路径唯一键 UPSERT；描述缓存使用 `(hash, type)` 冲突忽略，保留首个结果。
  PostgreSQL 使用其原生 UPSERT 和行锁，不执行 SQLite PRAGMA。
- 为三张媒体表补齐哈希索引，使 `hash OR path` 的两侧都可使用索引。
- 消息身份统一为 `(stream_id, message_id)`；聊天流本身已包含平台作用域。
  入站和历史写入采用可处理并发创建竞争的 `get_or_create`，查重条件与数据库唯一键一致，
  不会因历史行的 `platform=NULL` 重复插入。
- `get_or_create` 遇到完整性冲突后，只在新查询确实找到同一记录时接受竞争结果；
  回读不匹配、非完整性错误均重新抛出，不吞掉真实故障。

## 启动迁移

框架原有 Schema 同步阶段自动建立媒体哈希索引，并将具名的全局消息 ID 唯一索引
替换为流内唯一索引，保留普通 `message_id` 查询索引。先建立新约束，再移除旧约束。
SQLite 显式启动 DDL 事务，迁移失败则整体回滚；测试验证了删除旧索引后发生故障仍能
恢复原索引及数据。迁移不重建消息表，不修改历史消息 ID、主键、时间或内容。

本实例只读核对到的旧约束是可原位迁移的 `ix_messages_message_id`。
未知 SQLite 库若使用表内全局 UNIQUE，则明确拒绝自动重建历史大表；保留数据并报出
具体迁移要求，不静默移除约束。

## 验证与使用

- 核心、数据库、媒体、消息、API、Schema 及上次取消/停机回归：615 项通过、2 项跳过。
  跳过项为未配置独立 PostgreSQL 测试服务的既有集成测试。
- 覆盖真实写锁占用、完整事务重试、重试上限、取消与 BUSY 同时到达、连接回收、
  并发计数、路径/哈希冲突、缓存重复写入、消息创建竞争、跨流同 ID、旧库迁移及失败回滚。
- 加压复核曾发现只有数据库锁等待和重试时，短超时仍会被同进程写入竞争耗尽；
  已增加上述应用层队列，并验证等待者取消不占连接、不执行写入。
- 已发布 Mnemosyne 2.1.2 实际包全量回归：310 项通过、1 项跳过。
- SQLite 的原有类型漂移测试断言与现存“保留类型亲和性兼容”的实现不符；已改为验证
  原始值与列类型保持不变，没有更改该既有类型处理策略。
- 测试均使用临时数据库；生产库仅作只读结构、查询计划与冲突记录检查。

本次修改全部在主程序中，插件独立仓库与市场中的 Mnemosyne 2.1.2 无需更改。
部署主程序修复并重启后，启动阶段才会运行索引迁移；未在运行中的 Bot 上手工修改索引。
